## SDX M1 Release

We are happy to announce that the Secure Data Exchange has been released into Production.

To learn about how to get onboarded onto SDX, go to the [Secure Data Exchange Documentation](https://developer.gov.bc.ca/docs/default/component/aps-infra-platform-docs/concepts/secure-data-exchange/).

### What's New

- **Connection Status Visibility**: Once a connection request finishes being set up, users can now see its status directly, instead of having to check external systems or logs to find out if something went wrong.
- **Interim Single Sign-On Setup**: A temporary, simplified process now lets API consumers and providers connect through Common SSO while the fully automated solution is being built.
- **Reference Implementation Examples**: New sample implementations show teams building services on SDX exactly how to connect, exchange data, and use features like token exchange correctly.
- **Digital Signing & Verification**: Organizations can now digitally sign data they send and verify data they receive, confirming that exchanges are genuine and came from the expected source.
- **Shorter-Lived, Self-Healing Certificates**: Internal security certificates now expire every 48 hours and automatically retry renewal if it fails, lowering the risk of outages caused by expired credentials.
- **Standardized Organization Identity**: Organization identifiers are now aligned with government identity systems (IDIR/Entra) and linked to the public bodies registry, removing confusion about which organization is which.
- **Metrics & Monitoring Fix**: Fixed an issue that was blocking performance data from being collected properly, restoring visibility into system health and traffic.
- **Published API Standard**: A formal API design standard is now published for teams building on SDX, along with a companion style guide with rules to keep APIs consistent and secure.
- **Automated API Spec Validation**: A new tool automatically checks that a team's API specification meets SDX requirements before it goes live.
- **Token Exchange Verification**: The token exchange process was manually tested end-to-end in production to confirm it works correctly ahead of wider rollout.
- **New Developer Support Channels**: Two new support channels were added for the developer community to get help and release updates.
