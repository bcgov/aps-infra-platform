## SDX M1 Release

We are happy to announce that the Secure Data Exchange has been released into Production.

To learn about how to get onboarded onto SDX, go to the [Secure Data Exchange Documentation](/concepts/secure-data-exchange.md).

### Tools

- **Connection Status Visibility**: Once a connection request finishes being set up, users can now see its status directly, instead of having to check external systems or logs to find out if something went wrong.
- **Reference Implementation Examples**: New sample implementations (covering both configuration and backend setup) show teams building services on SDX exactly how to connect and exchange data correctly. To learn more, go to the [Reference Implementation Github Repo](https://github.com/bcgov/sdx-reference-impl).

### Edge Runtime Groups

- **Shorter-Lived, Self-Healing Certificates**: Internal security certificates now expire every 48 hours and automatically retry renewal if it fails, lowering the risk of outages caused by expired credentials.
- **Metrics & Monitoring Fix**: Fixed an issue that was blocking performance data from being collected properly, restoring visibility into system health and traffic.

### Token Exchange

- **Interim Single Sign-On Setup**: A temporary, simplified process now lets API consumers and providers connect through Common SSO while the fully automated solution is being built.
- **Token Exchange Verification**: The token exchange process was manually tested end-to-end in production to confirm it works correctly ahead of wider rollout.
- **Standardized Organization Identity**: Organization identifiers are now aligned with government identity systems (IDIR/Entra), removing confusion about which organization is which.

### Data Integrity

- **Data Access Protocol Updates**: The documentation describing how data is securely shared between organizations was revised based on developer and internal security feedback. View the [Data Access Protocol](reference/sdx/data-access-protocol.md) document.

### Organization Signing

- **Digital Signing & Verification**: Organizations can now digitally sign data they send and verify data they receive, confirming that exchanges are genuine and came from the expected source.

### SDX/CSIT - API Style Guide Governance

- **Published API Standard**: A formal API design standard was drafted, reviewed, and published to both internal and public-facing documentation sites. View the [SDX API Standard](https://developer.gov.bc.ca/docs/default/component/sdx-api-standards-techdocs) document.
- **Automated API Spec Validation**: A new tool automatically checks that a team's API specification meets SDX requirements before it goes live. Visit the [API Governance Github Repo](https://github.com/bcgov/itk-api-governance) for tools to validate APIs.
- **API Style Guide Ruleset**: New rules were added to the API style guide to help teams build consistent, secure APIs. View the [API Style Guides](https://developer.gov.bc.ca/docs/default/component/api-style-guides).
